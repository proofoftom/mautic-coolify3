# Mautic Coolify Service

Production-ready Coolify service configuration for Mautic 6 with support for custom themes and plugins through a git-based workflow.

## Overview

This configuration deploys a complete Mautic 6 stack including:
- **Mautic 6** (Apache variant with PHP 8.3)
- **MariaDB 10.11** database
- **RabbitMQ 3** message queue for async processing
- Three Mautic services: web, cron, and worker
- Support for custom themes and plugins via git

## Quick Start Guide

1. **Create a new Coolify service**:
   - In Coolify, create a new project and service
   - Select "Docker Compose" as the service type
   - Connect your Git repository containing this configuration

2. **Configure environment variables**:
   - Coolify will auto-generate the following secrets:
     - `SERVICE_PASSWORD_64_MYSQLROOT` - MySQL root password
     - `SERVICE_PASSWORD_64_MYSQL` - MySQL user password
     - `SERVICE_USER_MYSQL` - MySQL username
     - `SERVICE_PASSWORD_64_RABBITMQ` - RabbitMQ password
     - `SERVICE_URL_MAUTIC_80` - Your Mautic domain URL

3. **Deploy**:
   - Click "Deploy" in Coolify
   - Wait for the build and deployment to complete
   - Access Mautic at your configured domain

4. **Complete Mautic setup**:
   - On first access, Mautic will guide you through the initial setup wizard
   - Create your admin account
   - Configure email settings (see [Environment Variables Reference](#environment-variables-reference))

## Adding Custom Themes

Custom themes should be placed in the `themes/` directory.

### Theme Structure

Each theme must follow this structure:

```
themes/
└── your-theme/
    ├── config.json           # Theme metadata
    └── html/
        └── email.html.twig   # Email template (for email themes)
```

### Example Theme

An example theme is provided at `themes/my-custom-theme/`:

```json
{
    "name": "My Custom Theme",
    "author": "Your Name",
    "authorEmail": "your.email@example.com",
    "description": "A custom Mautic theme with email templates",
    "version": "1.0.0",
    "features": ["email"],
    "screenshots": []
}
```

### Steps to Add a New Theme

1. Create a new directory under `themes/` with your theme name
2. Create a `config.json` file with theme metadata
3. Add your template files (e.g., `html/email.html.twig`)
4. Commit and push to git
5. Redeploy in Coolify
6. Enable the theme in Mautic admin under Configuration > Themes

## Adding Custom Plugins

Custom plugins should be placed in the `plugins/` directory.

### Plugin Structure

Each plugin must follow this structure:

```
plugins/
└── YourPluginBundle/
    ├── YourPluginBundle.php     # Main bundle class
    └── Config/
        └── config.php           # Plugin configuration
```

### Example Plugin

An example plugin is provided at `plugins/MyPluginBundle/`:

```php
<?php
namespace Mautic\PluginBundle;

use Mautic\PluginBundle\Bundle\PluginBundleBase;

class MyPluginBundle extends PluginBundleBase
{
}
```

### Steps to Add a New Plugin

1. Create a new directory under `plugins/` with your plugin name (must end with `Bundle`)
2. Create the main bundle class (e.g., `YourPluginBundle.php`)
3. Create a `Config/config.php` file with plugin configuration
4. Commit and push to git
5. Redeploy in Coolify
6. Enable the plugin in Mautic admin under Plugins

## Adding Composer Dependencies

Additional PHP packages can be added via [`composer.json`](composer.json:1).

### Steps to Add a Dependency

1. Edit [`composer.json`](composer.json:1) and add your package to the `require` section:

```json
{
    "require": {
        "symfony/amazon-mailer": "^7.0",
        "your/package": "^1.0"
    }
}
```

2. Commit and push to git
3. Redeploy in Coolify (the Dockerfile will run `composer install` during build)

### Example: AWS SES Integration

The [`composer.json`](composer.json:1) already includes `symfony/amazon-mailer` for AWS SES integration. To configure:

1. Add the following environment variables in Coolify:
   - `MAUTIC_MAILER_DSN`: `ses://API_KEY:API_SECRET@default`
   - `MAUTIC_MAILER_FROM_EMAIL`: `your-email@example.com`
   - `MAUTIC_MAILER_FROM_NAME`: `Your Name`

## Coolify Configuration Steps

### 1. Create the Service

1. In Coolify, navigate to your project
2. Click "New Service" > "Docker Compose"
3. Connect your Git repository
4. Select the branch to deploy

### 2. Configure Environment Variables

Coolify will auto-generate the required secrets. You can also add custom variables:

- **Auto-generated by Coolify**:
  - `SERVICE_PASSWORD_64_MYSQLROOT`
  - `SERVICE_PASSWORD_64_MYSQL`
  - `SERVICE_USER_MYSQL`
  - `SERVICE_PASSWORD_64_RABBITMQ`
  - `SERVICE_URL_MAUTIC_80`

- **Custom variables you may add**:
  - `MAUTIC_MAILER_DSN` - Email service DSN
  - `MAUTIC_MAILER_FROM_EMAIL` - Default from email
  - `MAUTIC_MAILER_FROM_NAME` - Default from name

### 3. Configure Domain

1. In the service settings, add your domain
2. Coolify will automatically configure Traefik routing and SSL
3. The `SERVICE_URL_MAUTIC_80` variable will be set to your domain

### 4. Deploy

Click "Deploy" and wait for the build to complete. Coolify will:
- Build the custom Docker image with themes/plugins
- Start all services (web, cron, worker, database, RabbitMQ)
- Run Mautic migrations automatically
- Configure SSL via Let's Encrypt

## Rebuild and Redeploy Workflow

When you make changes to themes, plugins, or [`composer.json`](composer.json:1):

1. **Commit your changes**:
   ```bash
   git add .
   git commit -m "Add custom theme/plugin"
   git push
   ```

2. **Redeploy in Coolify**:
   - Navigate to your service
   - Click "Redeploy" (or "Deploy" if it's a new commit)
   - Wait for the build and deployment to complete

3. **Clear Mautic cache** (if needed):
   - In Coolify, access the service logs
   - Run: `php /var/www/html/docroot/bin/console cache:clear`

### Force Rebuild

To force a complete rebuild (ignoring Docker cache):
1. In Coolify, click "Redeploy" with "Force rebuild" option enabled

## Troubleshooting

### Deployment Fails

1. **Check service logs** in Coolify for error messages
2. **Verify environment variables** are properly set
3. **Ensure volume directories** exist on the server
4. **Check disk space** - builds can be large

### Mautic Not Accessible

1. **Verify domain configuration** in Coolify
2. **Check Traefik logs** for routing issues
3. **Ensure SSL certificate** was issued successfully
4. **Wait a few minutes** for DNS propagation

### Database Connection Errors

1. **Check MariaDB container** is healthy
2. **Verify database credentials** in environment variables
3. **Check network connectivity** between services

### Theme/Plugin Not Showing

1. **Verify file permissions** - should be owned by `www-data`
2. **Clear Mautic cache**: `php bin/console cache:clear`
3. **Check theme/plugin structure** matches requirements
4. **Verify files were copied** during build (check build logs)

### Cron Jobs Not Running

1. **Check mautic_cron container** is running
2. **Review cron container logs** for errors
3. **Verify RabbitMQ connection** is healthy

### Queue Worker Not Processing

1. **Check mautic_worker container** is running
2. **Review worker logs** for errors
3. **Verify RabbitMQ has messages** in the queue
4. **Check database connection** for the worker

### Performance Issues

1. **Increase PHP memory limit** via `PHP_MEMORY_LIMIT`
2. **Check MariaDB performance** - consider adding indexes
3. **Review RabbitMQ queue depth** - may need more workers
4. **Enable Mautic caching** in Configuration > System Settings

## Architecture

The service consists of 5 containers:

- **mautic_web**: Apache web server serving Mautic
- **mautic_cron**: Runs scheduled tasks (segments, campaigns, emails)
- **mautic_worker**: Processes background jobs via RabbitMQ
- **mysql**: MariaDB 10.11 database
- **rabbitmq**: Message queue for async processing

All services share a private Docker network and use persistent volumes for data storage.
